# Option for protocol V: separate validation data (code hash 598ac132e99f)

The protocols V0–V9, N and P0–P24 (and later Q, R, L, M, W, S50 and S100) were run with this code version,
whose code hash is `598ac132e99f`. Relative to the executed code of the other
4,820 runs (`de756535ee20`, archived in `executed_code/`), it adds one option:

* `fed.val_split_weighting` (default `false`). When `true`, each client splits
  its validation nodes once into two stratified random halves (fixed seed
  20261025 plus the client id, own random generator, so the global random state
  is untouched). The selection score that weights clients in Hard and Soft is
  computed on one half, and the validation AP that selects the checkpoint on
  the other. Files: `src/config.py`, `src/fed/client.py`.

With the option at its default the code is unchanged in behaviour:

* the option is left out of the configuration hash while it is `false`, so all
  earlier configuration hashes are reproduced (`tools/verify_release.py`, check 4);
* `tools/verify_release.py`, check 2, removes exactly these additions from the
  syntax tree of the released files and requires the rest to equal the executed
  code;
* running the same configuration with both versions gives bit-identical run
  records and saved scores (tested on protocol C0 before the runs).

Protocol N uses the existing option `fed.early_stop_enabled: false`, so the
federated models train all 300 rounds and keep their best checkpoint, as the
centralized models do. Protocols P0–P24 use only existing options (budget 2 on
the fixed partitions). The configurations are generated by
`tools/make_revision3_configs.py` and run by `tools/run_revision3.py`.
